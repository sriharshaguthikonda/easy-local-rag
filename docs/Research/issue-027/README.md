# Issue #27 verification audit

**Issue #27 remains open.** The maintained PyQt chat accepts every tested class of invalid answer. Streamlit rejects unknown standalone numeric citations at completion. Both applications display unchecked text while it streams and accept semantically unsupported answers with valid citation numbers.

Audited on 2026-11-27 at maintained GUI commit `656ae2a905cb4a400e66a9101663de546b2d17e0`, tree `0a560dd88fe0633fe0a8bba9c08ab9a22570923f`. The tree matches the independently verified #5 candidate `27959f498b95ca1095f8fff4ec93d50c7c0b2e81`. PyQt chat and maintained Streamlit chat are the surfaces tested. The full suite also exercises the other maintained entry points. [Issue #27](https://github.com/sriharshaguthikonda/easy-local-rag/issues/27), [#5 closure receipt](https://github.com/sriharshaguthikonda/easy-local-rag/issues/5#issuecomment-7218274040).

## Acceptance at the pinned commit

`Accepted` means the response was displayed and committed to assistant history. The probes used visibly different synthetic fixture texts, captured the request at the provider-client boundary, and drove the real router with an injected client. Streamlit results were checked through its synchronous helper and normal background completion path.

| Case | PyQt | Streamlit |
| --- | --- | --- |
| Invented standalone citation `[99]` | Accepted | Visible in the pending stream, rejected on completion with no history entry |
| Correct citation attached to an unsupported claim | Accepted | Accepted |
| Fabricated direct quotation with a valid citation | Accepted | Accepted |
| Claim contradicted by the cited chunk or conflict suppressed across two sent chunks | Accepted | Accepted |
| Confident answer to a question the low-score retrieved text does not answer | Accepted without citations | Accepted with a missing-citations warning |
| Citation `[2]` to a distinct candidate absent from the captured request | Accepted | Standalone `[2]` visible in the pending stream and rejected on completion. The composite `[2, 99]` is accepted with a missing-citations warning |
| Malformed answer JSON, empty response, or response ending with provider `finish_reason=length` | Accepted | Accepted |
| Empty retrieval, missing source text, or grossly oversized current evidence | Error before an answer completion call | Error before an answer completion call |
| Supported claim with `[1]` | Accepted | Accepted |

The excluded candidate was selected out in the fixture before request assembly. The request contained exactly one numbered evidence block and lacked the omitted source’s sentinel. This proves the application can display or commit a reference to evidence absent from its outbound request. Actual server-side truncation, model recall, error rates and real-world assertion quality were outside this offline experiment.

### D. Budgets, request visibility and medical-reference profile

Both use the shared router’s serialized-byte estimate and output reserve during profile selection. Ollama supplies explicit `num_ctx` and `num_predict`. These controls do not produce a per-turn manifest of evidence, an effective provider-context receipt, or a typed warning when a decisive source fails to make the cut.
