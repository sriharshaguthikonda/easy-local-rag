## Confirmed defects and existing guarantees

### Tokenizer and template accounting

Streamlit's helper tries `tiktoken.encoding_for_model`, falls back to `cl100k_base`, then to `int(words * 1.6)` on encoder or asset failure. It adds four tokens per message. Meta's Llama 3 reference uses its own vocabulary, role delimiters, turn separators and generation prefix. In the offline fixture, `cl100k_base` and Llama produced 14 and 13 tokens for one mixed Unicode string. A single 500-character CJK string measured 500 Llama content tokens and five app tokens including framing when the fallback asset was unavailable. Two regex counters remain defined in the maintained CLI backends. A call-site search at the pin found no maintained caller of either definition. ## Minimal implementation proposal

1. Reuse the generation profile and router. Add a verified tokenizer and chat-template revision per supported provider/model, with configured and effective context provenance and a separate output cap. Count the actual rendered system, complete admitted history, current query, serialized fenced evidence, role framing, and any provider schema/template overhead. Apply `input + reserved output <= effective context` per candidate. Use an explicitly proven conservative bound for unsupported formats where available. Otherwise surface a typed capacity failure. Keep organization TPM and request capacity separate.
2. Replace the Streamlit-only message trimming with shared admission before dispatch. Remove complete oldest history turns first and preserve the complete system/evidence/query envelope. For the first implementation, abstain when that protected envelope cannot fit. If whole-source admission becomes necessary later, select by existing retrieval order before freezing aliases and hashes, record exclusions, and validate against that exact package. Keep Chroma collection and chunk identities, #10 ranking, and #11 embedding provenance separate from generation tokenization.
3. Recheck the exact same admitted package, history and output reserve on each allowed same-provider attempt. Skip any replacement that cannot fit it. Keep #5's fenced, text-only, no-cross-provider dispatch and speech consent and #27's buffer-through-normal-stop and citation/span checks. Propagate typed context failures and record the attempted and actual model, limits, reservation, input counts, and both evidence hashes with each result.
4. Prefer a verified reject-on-overflow transport mode where the provider and SDK support it. Normalize terminal usage and truncation signals, explicitly account for cached tokens, and fail closed on explicit truncation or a discrepancy that implies content loss. A normal stop or matching token count alone cannot prove which source bytes the provider evaluated. Keep uncertain evidence out of accepted text, history, export, and speech.
